# Складно — иллюстрация из одной фразы

Веб-сервис собирает изометрические иллюстрации из готовой векторной библиотеки клиента (Figma-файл «Тестовое | иллюстрации»). Пользователь пишет метафору («Вечер с книгой») или просто перечисляет объекты («кошелёк, монета») — сервис подбирает объекты библиотеки, раскладывает их по правилам из эталонных композиций и даёт отредактировать и скачать результат в SVG. Новые объекты не генерируются: в композиции только элементы библиотеки, геометрия которых не меняется.

**Работающий сервис: https://skladno.qaprovider.com**

Постановка задачи — [`docs/TZ.md`](docs/TZ.md), макеты — [`design/`](design), примеры результатов — [`examples/`](examples).

## Известные ограничения

- Нет отмены (undo). Смена формата кадра, «Другой вариант» и «Изменить объекты» заново раскладывают сцену: ручные перемещения и повороты при этом сбрасываются.
- Раскладка считается в основном потоке браузера: около 20–40 мс для 2–5 объектов, до ~185 мс для 8.
- Лимиты AI-запросов и кэш ответов хранятся в памяти процесса и обнуляются при перезапуске сервера.
- За обратным прокси (nginx) обязательно `TRUST_PROXY=1`, иначе сервер видит адрес прокси и все пользователи делят один IP-лимит.
- Пропорции объектов — 1:1 к библиотеке. В SVG-drop-фреймах клиента лампа уменьшена (≈0,7) и ручка увеличена (≈1,6) относительно остальных, но на странице «Примеры композиций», где записано правило «нельзя менять пропорции объектов относительно друг друга», все 18 композиций нарисованы строго 1:1 к библиотеке. Сервис следует странице правил и сохраняет 1:1. Чтобы высокая лампа не уходила за край, раскладка обрезает высокие объекты только снизу: голова лампы и большая часть стойки всегда в кадре (при необходимости вся сцена равномерно уменьшается).

## Возможности

- **Сценарий 2 — список объектов.** «Кошелёк, монета», «книгу, лампу и ручку», «две монеты», «кошелёк на фоне книги» разбираются локальным словарём без сетевых запросов: синонимы, падежи и числа словами и цифрами («три монеты», «5 монет», не больше пяти), слова «на фоне» делают объект фоновым: «книга на фоне» и «книга фоном» — объект перед словом, «на фоне книги», «фоном книга» — объекты после него в той же части фразы (до запятой). Явное «на фоне» побеждает и роли, которые выбрал AI.
- **Сценарий 1 — метафора или заголовок.** Фраза уходит на сервер, LLM возвращает только JSON со списком id объектов библиотеки и их ролями (главный / фоновый) — никаких координат и новых объектов. Без ключей или после лимита работает словарь смыслов (кошелёк → деньги, накопления, покупки…).
- **Композиция.** Детерминированный движок: формат кадра (квадрат, горизонтальный, вертикальный), детализация S/L, три цветовые схемы клиента, «Другой вариант» — альтернативная раскладка тех же объектов.
- **Редактор на холсте.** Перетаскивание (мышь и touch), панель у выбранного объекта: поворот, дубль, выше/ниже по слоям, главный ↔ фоновый, другие цвета схемы, удаление. «Изменить объекты» — добавить или убрать элементы библиотеки.
- **Своя палитра.** Список hex-цветов или JSON-файл; перекраска идёт через те же роли, что и у встроенных схем.
- **Экспорт SVG.** Чистый векторный файл: каждый объект — отдельная именованная группа `<g>` с `transform`, исходные пути, цвета подставлены значениями. Без CSS-переменных, растра и `foreignObject` — открывается и редактируется в Figma.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev                 # разработка: http://localhost:5173 (сервер + Vite в одном процессе)
npm run build && npm start  # продакшен: один процесс node, отдаёт API и собранный фронтенд
```

Ключи LLM необязательны: без них сервис полностью работает в словарном режиме. Чтобы подключить AI, скопируйте `.env.example` в `.env` и заполните `ANTHROPIC_API_KEY` и/или `DEEPSEEK_API_KEY`. Порядок провайдеров — `LLM_PRIMARY` / `LLM_FALLBACK`.

Другие команды:

```bash
npm run extract       # пересобрать библиотеку из assets/source/*.svg
npm run examples      # отрисовать примеры композиций в examples/
npm run checks        # контрольные композиции в build/checks/ (SVG + PNG через headless Chrome, если он установлен)
npm test              # тесты (vitest), прогресс сохраняется в build/test-logs/_passed.json
npm run test:resume   # продолжить прерванный прогон: пропускает файлы, уже прошедшие на том же дереве файлов
npm run compare-llm   # сравнить провайдеров на 20 фразах (нужны ключи) → build/llm-compare.md
```

## Архитектура

```
assets/source/          экспорт из Figma: size-L.svg, size-S.svg (библиотека), examples.svg (эталоны), svg-drop/
scripts/extract-library.ts   извлечение библиотеки (повторяемое)
library/svg/{L,S}/{main,background}/*.svg   по SVG-файлу на объект × вариант × размер (исходные цвета)
src/library/generated/  manifest.json + library-{L,S}.json — то, чем пользуется приложение
src/shared/             общий код клиента и сервера: каталог смыслов, палитры, движок раскладки, рендер SVG, словарь
src/server/             Node-сервер: /api/interpret, лимиты, кэш, провайдеры LLM, раздача фронтенда
src/client/             React-интерфейс
tests/                  vitest
```

### Хранение и извлечение SVG-элементов

Исходники — секции Figma, выгруженные в SVG с именами слоёв в `id`. Скрипт `scripts/extract-library.ts`:

1. Разбирает SVG собственным минимальным XML-сканером, который помнит байтовые смещения каждого элемента, — поэтому разметку объекта можно скопировать из исходника как есть.
2. Декодирует имена слоёв: Figma пишет UTF-8-байты кириллицы как Latin-1-сущности (`&#208;&#154;…` → «Книга»). Суффиксы `_2`, `_3` — повторы имени; главный или фоновый вариант определяется положением группы относительно заголовка «Фоновые объекты». Безымянные группы (`Group 21361363xx`) сопоставлены с объектами вручную по виду и пропорциям — таблица `UNNAMED_GROUPS` в `scripts/lib/library-source.ts`.
3. Читает три образца палитры (сетка 2×4: левая колонка — цвета фона, правая — цвета объектов) и три фона схем.
4. Для каждого объекта сохраняет внутреннюю разметку группы и заменяет **только** значения `fill`/`stroke` на токены ролей (`var(--bgLight)`, `var(--accent1)`…); `id` слоёв убираются, чтобы объект можно было вставить дважды. Остальные байты — пути, `rect`, атрибуты — остаются ровно такими, как их выгрузила Figma (тест восстанавливает исходник из библиотеки и сравнивает строку целиком).
5. Считает точный bounding box (с экстремумами кривых Безье) — это собственный viewBox фрагмента в исходных единицах, — и выпуклый контур объекта, по которому движок оценивает перекрытия и обрезку кадром.
6. Пишет `manifest.json` (id, русское и английское имя, синонимы, теги смыслов, вариант, размер, габариты, роли цветов), `library-L.json` / `library-S.json` (разметка с ролями, габариты, контуры, элементы декора фона) и отдельные SVG-файлы для просмотра.

Объекты никогда не масштабируются относительно друг друга: у сцены один общий масштаб, а размеры фрагментов — их истинные размеры из Figma. S-версии — другие, менее детальные фрагменты из `size-S.svg`; разница S и L только в детализации. Кадр, раскладка и размер каждого объекта у S и L одинаковые: лист S нарисован примерно вдвое мельче, и каждый S-фрагмент рисуется со своим коэффициентом «размер L ÷ размер S» (поле `detail`, считает скрипт извлечения), так что он ровно того же размера, что и L-версия. S-композиция раскладывается по геометрии L и отличается от L только фрагментами. Переключение S/L меняет только фрагменты: позиции, ручные перемещения и повороты не меняются.

### Перекраска

Цвет в библиотеке — это роль, а не значение: `bgLight`, `bgMid`, `bgDark`, `ink` (колонка «Цвета фона») и `accent1`–`accent3`, `paper` (колонка «Цвета объектов»). Схема — словарь «роль → hex». Смена схемы или загрузка своей палитры просто подставляет другой словарь; геометрия не трогается. Соответствие ролей проверено по svg-drop-фреймам клиента, где те же объекты уже перекрашены в персиковую и бирюзовую схемы.

Правила схемы соблюдаются конструктивно: фон кадра и фоновые (монохромные) объекты используют только роли фона; главные объекты могут использовать любые роли схемы. Для своей палитры сервис отклоняет набор, в котором цвет объектов совпадает с цветом фона. «Другие цвета» у главного объекта — это перестановка ролей внутри схемы (так в эталонах кошелёк бывает сиреневым и жёлтым), за пределы схемы она не выходит. Объект, почти целиком окрашенный в светлый цвет фона (сиреневый кошелёк), по умолчанию получает такую перестановку, чтобы не сливаться с фоном — как в эталонах клиента.

### Движок композиции

`src/shared/layout.ts`, без AI и без случайности: одинаковый вход — одинаковая сцена.

- Кадры взяты из `examples.svg`: 1000×1000, 1200×630, 800×1200 — одинаковые для S и L. В эталонах объекты стоят в масштабе 1:1 к библиотеке, крупные (книга, папка) обрезаются краем кадра, фоновые объекты прижаты к краю и видны примерно наполовину.
- Общий масштаб подбирается так, чтобы главные объекты занимали около трети кадра (не больше 1,3 и уменьшается, если объекты не помещаются без наложений).
- Стартовые позиции — шаблоны по числу главных объектов, снятые с эталонов (крупный объект ниже-левее, мелкие выше-правее и т. п.); «Другой вариант» зеркалит шаблон, меняет альтернативный шаблон и стиль декора фона.
- Затем детерминированный поиск по шаблону сдвигает объекты, минимизируя штрафы: главные объекты целиком в кадре с полем (самый крупный может быть обрезан, как в эталонах), без заметных наложений главных друг на друга, фоновые видны на 30–60 %, композиция сбалансирована по центру.
- Глубина. Все объекты стоят на одной плоскости, поэтому глубину задаёт «основание» — нижняя точка тела объекта без отбрасываемой тени (контур тела без тени считается при извлечении библиотеки, поле `body`). Чем ниже основание на экране, тем ближе объект к зрителю.
- Порядок слоёв: фоновые позади, внутри групп — по основанию. Для любых двух перекрывающихся объектов тот, что нарисован позже, стоит ближе (основание ниже); для пары фоновый/главный это обеспечивает поиск (жёсткий штраф с запасом 2 % высоты кадра), иначе главный объект выглядел бы стоящим на фоновом.
- Главный объект закрывает не больше 18 % тела фонового (по контурам без теней; в эталонах наушники заходят на угол вазы, монета касается подставки лампы). Фоновые слоты — сверху и по верхним краям кадра, как в эталонах; если раскладка не выходит, движок пробует другие слоты, потом уменьшает общий масштаб.
- Масштаб один на всю сцену, у главных и фоновых объектов одинаковый: соотношение размеров берётся из библиотеки (например, L-наушники 888×691 против кошелька 630×396 — так же и в `examples.svg`).
- Смена формата пересобирает сцену заново, смена детализации S/L сохраняет расстановку (и ручные перемещения) и меняет только сами фрагменты и общий масштаб.
- Декор фона (конфетти, линии, клин) взят из фонов схем в библиотеке и привязан к углам кадра, поэтому переносится на любой формат.

### Интерпретация фразы

- `src/shared/matcher.ts` — словарь: нормализация, лёгкий стеммер для русских окончаний, сравнение с допуском (префикс и одна правка для длинных основ — покрывает беглые гласные «кошелёк / кошелька»), числа и «на фоне». Если все значимые слова — названия объектов, это сценарий 2 и запрос в сеть не делается.
- Иначе клиент вызывает `POST /api/interpret`. Сервер (`src/server/interpret.ts`) нормализует фразу и ищет её в кэше, проверяет лимит, вызывает провайдеров по порядку и в конце всегда может ответить словарём смыслов. Кэш общий для всех посетителей, поэтому в модель уходит ровно нормализованная строка, из которой сделан ключ кэша (строчные буквы, цифры и пробелы): дописать к безобидной фразе инструкцию, которую нормализация выбросит (другой алфавит, переводы строк, кавычки), и отравить ответ для всех нельзя.
- Защита API (`src/server/guard.ts`): `POST` принимается только с `Content-Type: application/json` (иначе 415) и отклоняется с 403, если `Sec-Fetch-Site` или `Origin` указывают на чужой сайт, — чужая страница не может тратить AI-лимит своих посетителей. Собранный фронтенд отдаётся с Content-Security-Policy (`default-src 'self'`, шрифты Google Fonts, `object-src 'none'`, `frame-ancestors 'none'`).
- Провайдеры (`src/server/llm/providers.ts`) за одним интерфейсом: Anthropic `claude-haiku-5-5` через официальный `@anthropic-ai/sdk` со структурированным выводом по JSON-схеме и DeepSeek через OpenAI-совместимый `/chat/completions` с `response_format: json_object`. Ответ любого провайдера проходит одну проверку (`parseAnswer`): только известные id, максимум 5 объектов, хотя бы один главный. Ответ ограничен 150 токенами; если модель упёрлась в этот потолок (`stop_reason: max_tokens`, у DeepSeek `finish_reason: length`), запасной провайдер не вызывается — отвечает словарь, чтобы один запрос не стоил дважды. Клиент тоже пропускает в сцену только id из библиотеки.
- Лимиты: 3 AI-запроса на браузер (cookie `skl_id` + счётчик на сервере), 10 на IP и 300 на весь сервис в скользящем окне 24 часа (`AI_LIMIT_PER_BROWSER`, `AI_LIMIT_PER_IP`, `AI_LIMIT_GLOBAL`). Общий лимит — потолок суточных трат: после него все фразы-метафоры разбираются словарём, как при исчерпанном личном лимите. Каждый запрос возвращается ровно через сутки после того, как был сделан. После AI-ответа интерфейс показывает, сколько запросов осталось; когда лимит исчерпан — что фраза разобрана по словарю и во сколько AI снова станет доступен. Повтор той же фразы берётся из кэша и лимит не тратит. Общий лимит запросов к API — 30 в минуту с IP. Счётчики и кэш хранятся в памяти процесса; устаревшие записи счётчиков регулярно вычищаются, а число ключей ограничено, так что память не растёт.
- Время ответа. У всей цепочки провайдеров один дедлайн — `LLM_DEADLINE_MS`, по умолчанию 12 с; провайдеры не повторяют запросы, запасной получает только оставшееся время (и не запускается, если осталось меньше секунды). Не уложились — сервер отвечает словарём с пометкой «AI не ответил вовремя». Клиент ждёт сервер не дольше 15 с и тоже собирает по словарю. Подсказки сервера («Совпадений в словаре нет…», «AI не ответил вовремя…») показываются пользователю над холстом.
- Провайдеры создаются один раз при старте сервера и переиспользуются всеми запросами.

### Интерфейс

React + TypeScript (Vite). Сцена — обычный SVG в DOM; та же функция `sceneToSvg`, что строит файл для скачивания, задаёт трансформации и на холсте, поэтому скачивается ровно то, что видно. Перетаскивание — Pointer Events (мышь и touch). Вёрстка адаптивная: телефон (одна колонка, «Скачать SVG» закреплена внизу, панель объекта над ней), планшет, десктоп.

## Тесты

`npm test` запускает `scripts/run-tests.mjs`: каждый файл `tests/*.test.ts` идёт отдельным процессом vitest, каждый PASS сразу записывается в `build/test-logs/_passed.json` вместе с отпечатком рабочего дерева; `--resume` пропускает файлы, уже прошедшие на том же дереве. Покрыто: декодирование имён и манифест, побайтовая сохранность геометрии, словарь на словоформах, инварианты раскладки (всё из библиотеки, один масштаб, видимость, наложения, порядок слоёв, детерминизм), правила цвета для всех схем, валидность экспортируемого SVG, разбор палитр, цепочка провайдеров, кэш и лимиты, защита общего кэша от инъекций в фразе, отказ межсайтовым запросам (415/403), потолок трат (150 токенов, без запасного провайдера после обрезанного ответа, суточный лимит сервиса), CSP, XML-безопасный заголовок SVG и фильтр id на клиенте.

## Использованные AI-инструменты

- **Claude Code** (модель Claude Opus) — разработка, тесты, ревью кода, деплой.
- **ChatGPT** — UX-концепция первого экрана, макеты интерфейса ([`design/`](design)) и фавиконка.
- **Внутри сервиса** для разбора метафор — Claude Haiku 5.5 (основной провайдер) и DeepSeek (запасной); сравнение моделей — `npm run compare-llm`.
